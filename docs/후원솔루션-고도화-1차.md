# 나눔플러스 후원솔루션 고도화 — 1차 (2026-08-25)

기존 코드는 이미 성숙(멀티기관·문자후원·계좌이체·정기·캠페인·QR·통계·정산·마스킹).
이번 1차에서는 **후원페이지 빌더 / 핵토 결제 재편 / 카드 정기(빌링키) / 통합 스키마 기반**을 추가했다.

## 적용 방법 (로컬에서 실행 — 중요)
새 테이블/컬럼이 추가되어 반드시 DB에 반영해야 동작한다.
```bash
npm run db:push       # DonorAccount, DonationPage, BillingKey + 컬럼/enum 반영
npm run db:emma       # (db:push 후) EMMA 테이블 재설치 — 기존 규칙 유지
npm run build         # prisma generate + next build (타입 정상 확인)
npm run dev           # http://localhost:3005
```
> db:push 는 비파괴적 변경(모두 신규/optional)이다. 다만 db:push 는 스키마에 없는 em_* 테이블을 지우므로 반드시 db:emma 재실행.

## 무엇이 바뀌었나

### 1) DB 스키마 (prisma/schema.prisma)
- enum DonationChannel 에 `RECURRING_CARD`(신용카드 정기) 추가
- enum `RecurringMethod { TRANSFER, CARD }` 추가
- **DonorAccount** (플랫폼 통합 후원자 계정, 카카오/네이버 로그인용 — 2차에서 로그인 연결)
- **DonationPage** (후원페이지 빌더 설정 1:1)
- **BillingKey** (카드 빌링키 참조 저장 — 카드 원문은 저장 안 함)
- Donor/Donation/RecurringDonation 에 donorAccountId 등 관계 필드, RecurringDonation.method/billingKeyId 추가

### 2) 핵토(Hecto) 결제 어댑터 (src/lib/adapters/)
- `hecto-transfer-mock.ts` — 내통장결제(간편 계좌이체 + 계좌 정기)
- `hecto-billing-mock.ts` — 카드 빌링키(발급/청구/삭제)
- `index.ts` — getTransferAdapter(), getBillingAdapter() 팩토리. 기본 mock.
- 실연동: `.env` 에 `HECTO_TRANSFER_PROVIDER=live` / `HECTO_BILLING_PROVIDER=live` + `HECTO_WEBHOOK_SECRET` 설정 후 `*-live.ts` 구현.
- 간편이체/정기이체 init 라우트는 이제 핵토 어댑터 사용(기존 온기는 레거시로 유지).
- 신규 라우트: `POST /api/donations/card/init` (카드 정기 = 빌링키 발급+첫 청구).

### 3) 후원페이지 빌더
- 기관 메뉴 **후원페이지 설정** (`/org/donation-page`)
- 설정 API `GET/PATCH /api/org/donation-page`
- 커스터마이징: 테마색 · 대표배너/문구 · 기관소개 · 스토리 블록(글/인용/이미지) · 추천 후원금액 · 노출 후원방법(채널 토글) · 감사 메시지 · 모금현황/캠페인/FAQ 노출 토글 · 공개여부
- `/donate/[기관slug]` 이 설정값으로 동적 렌더(테마색 반영). 비공개 시 준비중 안내.
- 캠페인 상세도 캠페인 allowedChannels + 기관 테마 반영.

### 4) 문자후원(요청 재확인)
- 이미 모바일은 sms: 링크로 문자앱 연결, **PC는 '문자 앱 열기' 버튼 숨김 + 안내문** (요청대로 유지).

## 다음(2차) 예정
- **후원자 간편로그인**: 카카오/네이버로 후원자(DonorAccount) 로그인, 후원자 마이페이지(내 후원내역/정기/빌링키 관리) — 관리자 로그인과 분리.
- **후원자 관리 고도화**: 세 채널 통합 기반 후원자 프로필/세그먼트/타임라인, 계정 연동 표시.

## 검증

# 2차 (2026-08-25) — 후원자 간편로그인 + 후원자 관리 고도화

## 인증 분리 (중요)
- **관리자** = 이메일/비밀번호(Credentials), **후원자** = 카카오/네이버/구글 OAuth.
- OAuth 로그인은 항상 **후원자(DonorAccount)** 로 처리(관리자 화면엔 OAuth 버튼 없음). 후원자 세션 role="DONOR", /admin·/org 는 미들웨어 차단.
- OAuth 실동작 조건: `.env` 의 KAKAO/NAVER/GOOGLE 키(이미 있음) + 각 콘솔에 콜백 URL 등록 필요:
  - `${NEXTAUTH_URL}/api/auth/callback/kakao`
  - `${NEXTAUTH_URL}/api/auth/callback/naver`
  - `${NEXTAUTH_URL}/api/auth/callback/google`
  - `NEXTAUTH_URL` 이 실제 접속 도메인과 일치해야 함.

## 후원자 기능
- 후원자 로그인 `/donor/login` (카카오/네이버/구글 버튼)
- 후원자 마이페이지 `/my`: 누적 후원·후원기관 수·정기후원 수 요약, 후원 내역(전 기관 통합), 정기후원 해지, 등록 카드(빌링키) 삭제.
- 후원자 API: `POST /api/donor/recurring/[id]/cancel`, `DELETE /api/donor/billing/[id]` (본인 소유 검증).
- 후원페이지/캠페인에서 로그인 시 이름·이메일 자동 채움 + "카카오·네이버로 로그인" 안내.
- 공개 헤더: 후원자=마이페이지, 관리자=대시보드, 비로그인=후원자 로그인/기관 로그인 분기.
- 로그인 상태로 후원하면 Donation/RecurringDonation/BillingKey 에 donorAccountId 연결.

## 후원자 관리 고도화 (기관측 /org/donors)
- 상단 요약: 전체 후원자·정기후원자·이번달 신규·누적 후원금.
- 목록: 정기/간편로그인 연동 배지, 누적·건수·최근후원, 필터칩(전체/정기/연동), 검색.
- 상세 드로어: 요약(누적/건수/정기/최근) + 채널별 건수 분포 + 최근 후원 타임라인 + 메모.

## 알려진 후속 개선(다음)
- 로그인 후원자의 Donor 중복: 현재 후원 시마다 Donor 행 생성(기존 설계). 로그인 후원자는 (org+donorAccount)로 find-or-create 하도록 개선 여지. 단 /my 집계는 donorAccountId 기준이라 정확.
- 핵토/문자 실 API 연동(live 어댑터), 카드 결제창 리다이렉트 플로우.

## 검증(2차)
- tsc 전체 재실행: 진짜 회귀 0. 남은 오류는 전부 Prisma 재생성 전 신규모델/필드 참조(build 후 사라짐).

# 3차 (2026-08-25) — 채널별 정산주기 설정 (최고관리자)

## 무엇이 바뀌었나
- 정산 시점이 하드코딩(문자 +3개월 16일, 나머지 다음달 16일)에서 **채널별 설정값**으로 변경.
- 최고관리자 화면: 정산 관리(`/admin/settlements`) 우측 상단 **정산주기 설정** 버튼 → `/admin/settlements/rules`.
- 규칙 형태(플랫폼 전역, 채널별):
  - 후원일로부터 N일 후 (DAYS) — 예: 문자후원 후원일 +5일
  - N개월 후 매월 M일 (MONTHS) — 예: 다음 달 16일(=1개월 후 16일), 3개월 후 16일
- API: `GET/PUT /api/admin/settlement-rules`.
- 스키마: enum SettlementRuleType(DAYS/MONTHS), model SettlementRule(channel@unique, ruleType, offsetValue, anchorDay).
- 정산 그룹 단위: (기관, 정산예정일) — Settlement 유니크를 (org, period)→(org, scheduledDate)로 변경. period(YYYY-MM)는 화면 표시용으로 유지(월별 뷰/포맷 그대로).
- 적용 시점: 저장 후 **새로 생성되는 정산**부터. 기존 정산 예정일은 불변. 미설정 채널은 기존과 동일한 기본값.

## 적용 (한 번 더 필요)
```
npm run db:push    # SettlementRule 테이블 + Settlement 유니크 변경 반영
npm run build      # 또는 dev 재시작
```

## 검증(3차)
- tsc: 진짜 로직 오류 0. 남은 9건은 전부 SettlementRule 재생성 전 연쇄 → db push 후 사라짐.
- 이전 배치(1·2차)는 이미 db push 완료됨(클라이언트에 DonationPage/DonorAccount/BillingKey 존재 확인, 06:19 재생성).

# 4차 (2026-08-27) — 후원페이지 전용 사이트화

## 핵심
- 후원페이지가 **기관 전용 미니사이트**로 전환. 플랫폼 공용 헤더/푸터 제거, 좌상단 로고+기관명, 우측(PC)·상단(모바일) 로그인, 기관정보 푸터, 외부 이탈 차단.
- 신규 컴포넌트 `DonateShell`(레이아웃+로그인 모달). 네비: 홈 / 모금 캠페인(그 기관 캠페인 모아보기) / 마이페이지.

## 페이지 구조 (셸 내부)
- `/donate/[org]`            홈: 배너·기관 소개·통계·후원 버튼·링크버튼·스토리·문자후원 피드
- `/donate/[org]/campaigns`  그 기관 캠페인 모아보기
- `/donate/[org]/campaigns/[slug]` 캠페인 상세(셸 유지)
- `/donate/[org]/my`         후원자 마이페이지(내역·정기해지·카드삭제·기본설정)

## 세부
- 후원페이지 빌더 확장: 로고 교체(logoUrl), 홈페이지·SNS 링크 버튼(links, 새 탭), 문자후원 피드 토글(showSmsFeed).
- 문자후원: 모바일 전용, 클릭 시 문구 4개("후원합니다/함께하겠습니다/응원합니다/사랑을 전합니다") + 직접입력 선택 → 기관 문자번호+문구 채워 문자앱 열림. PC는 번호 안내(작동 안 함).
- 후원 버튼 모바일 2열 그리드로 변경(글씨 잘림 해결).
- 후원자 로그인: 카카오/네이버(작동) + 이메일=준비중 팝업(소셜 안내). 로그인 모달은 셸 내장.
- 후원자 기본설정: 프로필(이름·연락처) 수정 API `/api/donor/profile`.
- 외부 이탈 차단: 셸엔 플랫폼 링크 없음. 기관 홈페이지/SNS만 새 탭 예외.
- 후원은 해당 기관 귀속(orgId 스코프 유지).

## 적용 (db push 필요 — DonationPage 신규 컬럼)
```
npm run db:push   # DonationPage.logoUrl, links, showSmsFeed 추가
npx prisma generate  (dev 꺼진 상태에서)
```
> tsc 0 오류. 단 저장 로직 특성상 신규 컬럼은 db push 후 런타임에서 동작.
