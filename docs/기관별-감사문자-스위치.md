# 기관별 감사 문자(MT) 스위치 — 적용 가이드

작성일: 2026-09-03 · 관련 점검 보고서: `docs/EMMA-MT-점검보고서.md`

---

## 1. 왜 만들었나

감사 문자 발송을 제어하는 수단이 전역 환경변수(`INFOBANK_MT_SENDER_NUMBER`) 하나뿐이었다.
이 값을 채우는 순간 **173개 기관 전체**에서 동시에 문자가 나가기 시작하고,
기관 단위로 빼거나 넣을 방법이 없으며, 발송된 문자는 취소할 수 없다.

→ 최고관리자가 화면에서 **전역 마스터 + 기관별**로 켜고 끌 수 있게 한다.

---

## 2. 동작 구조

```
문자후원 수신(MO)
   ↓
Donation 생성
   ↓
[게이트]  전역 마스터 ON?  ──아니오──▶ 발송 안 함
   ↓ 예
[게이트]  기관 스위치 ON?  ──아니오──▶ 발송 안 함
   ↓ 예
[게이트]  기관 발신번호 있음? ──아니오──▶ 발송 안 함
   ↓ 예
em_smt_tran 큐 INSERT  →  EMMA가 픽업해 발송
```

**발신번호는 기관별 필수** — 공용 번호 폴백이 없다. 등록하지 않은 기관은 발송 대상에서 제외된다.

### 설계 원칙

- **Fail-closed** — 설정을 읽지 못하면(테이블 미적용, DB 오류) 발송하지 않는다.
- **발신번호 기관별 필수** — 전기통신사업법상 발신번호 사전등록제가 적용되므로,
  기관이 소유·이용 권한을 가진 등록된 번호만 쓸 수 있다. 플랫폼 공용 번호로
  기관 이름의 문자를 대신 보내지 않는다(회신·문의가 엉뚱한 곳으로 간다).
  발신번호가 없으면 스위치를 켤 수도 없다.
- **기본값 OFF** — 신규/기존 기관 모두 꺼진 상태로 시작한다.
- **차단은 큐 적재 이전** — `em_smt_tran` 에 들어간 뒤에는 EMMA가 집어가므로 되돌릴 수 없다.
- **최종 안전장치** — `sendEmmaMt()` 내부에서도 한 번 더 확인한다. 기관 ID가 없는 발송 요청은 차단한다.
  (`em_smt_tran` 에 INSERT 하는 경로는 이 함수뿐이므로 마지막 방어선이다)

## 5. 발송 개시 절차 (권장)

1. `/admin/settings/emma` → **MT 발송 큐 상태** 패널에서 `em_smt_tran` 정상 여부 확인
2. `emma_id` 정합 확인 — EMMA 실제 기록값은 **공백**, 코드는 `'na'` (점검 보고서 5항)
   → 이 불일치를 먼저 해결하지 않으면 큐에 쌓이기만 하고 발송되지 않는다
3. 전역 **기본 발신번호** 입력 (예: `07041582540`)
4. **시험 기관 1곳만** 켠다 → 실제 문자후원 1건으로 도달 확인
5. 문제 없으면 대상 기관을 늘리고, 마지막에 전역 마스터를 켠다
6. 마스터를 켜기 직전 `em_smt_tran` 잔여분 확인 — 과거 큐가 남아 있으면 일괄 발송된다

```sql
SELECT msg_status, count(*) FROM em_smt_tran GROUP BY 1;
```

## 8. 검수 결과 (2026-09-03)

### 8-1. EMMA 큐 픽업 규칙 — `emma_id` 는 반드시 **공백**

EMMA 3.7 저장 프로시저 `sp_em_smt_tran_select` (`emma-sql/emma_sp_smt.sql:563`) 원문:

```sql
WHERE priority = '<p_priority>'
  AND msg_status = '1'
  AND date_client_req < now()
  AND date_client_req > now() - interval '<ttl> minute'
  AND emma_id = ' '                         -- ★ 공백인 행만 조회
...
UPDATE em_smt_tran SET emma_id = p_emma_id  -- EMMA가 선점하며 자기 ID를 찍는다
```

`emma_id` 는 **우리가 채우는 값이 아니라 EMMA가 선점 표시로 찍는 값**이다.
기존 코드는 `.env` 의 `EMMA_ID`("nanum")를 2자리로 잘라 `'na'` 를 넣었는데,
`EMMA_ID` 는 인포뱅크 **인증 ID**(`emma.cf` 의 `auth.id`)이지 이 컬럼 값이 아니다.
→ `mt-sender.ts` 를 공백(`'  '`) 삽입으로 수정.

부수 확인:
- `priority` 는 컬럼 기본값 `'S'`(standard)로 들어가며, `emma.cf` 의
  `que.name.smsmt.s` / `priority.cnt.sms.normal=1` 설정과 일치한다. ✔
- INSERT 가 채우지 않는 NOT NULL 컬럼(`input_type`, `priority`, `country_code`)은
  모두 DEFAULT 가 있어 제약 위반이 없다. ✔
- `date_client_req > now() - interval '<ttl>'` 조건이 있어 **오래된 큐는 자동으로 만료**된다.

### 8-2. SMS 90바이트 초과 — 기존 문구는 대부분의 기관에서 잘림

`emma.cf` 의 `gw.charset = EUC-KR`, `service_type='0'`(SMS)은 **90바이트** 제한.

| | 기존 문구 | 변경 후 |
|---|---|---|
| 고정부(기관명 제외) | **81 바이트** | 38 바이트 |
| 기관명 여유 | 9바이트 (한글 4자) | 52바이트 (한글 26자) |
| 실제 기관명 표본 10개 | **8개 초과** | 0개 초과 |

변경 문구: `[나눔플러스] {기관명} 3,000원 후원 감사합니다.`
`buildThankYouMessage()` 가 EUC-KR 바이트를 계산해 조립하며, 기관명이 길면
2바이트 문자를 쪼개지 않고 안전하게 자른다. 결과는 항상 90바이트 이하.

## 9. 문구 및 발신번호 정책 (2026-09-03 확정)

### 9-1. 문구 — 기관명을 맨 앞에

```
[방배노인종합복지관] 3,000원 후원 감사합니다.
```

문자 앱에서 대괄호 첫머리가 발신 주체로 읽히므로, 후원자가 "내가 후원한 그 기관이
보낸 문자"로 인식한다. 실측 표본 11개 기준 최대 **89바이트**, 90B 초과 0건.
기관명이 지나치게 길면 **기관명만** 줄이고 안내 문구는 보존한다.

| 문구 | 고정부 | 기관명 여유 | 최대 |
|---|---|---|---|
| (구) `[나눔플러스] {기관} 3,000원을 후원해 주셔서…` | 81B | 9B(한글 4자) | **초과** |
| (신) `[{기관}] 3,000원 후원 감사합니다.` | 27B | 63B(한글 31자) | 89B |

### 9-2. 발신번호 — 기관별 필수, 폴백 없음

- 기관 상세 화면에서 기관마다 등록한다. **미등록 기관은 발송되지 않는다.**
- 미등록 상태에서는 감사 문자 스위치를 켤 수 없다 (API·UI 양쪽에서 차단).
- 화면에 **발신번호 사전등록제 안내**를 상시 표시한다.
- 형식 검증(`validateSenderNumber`): 오타로 인한 발송 실패만 걸러낸다.
  실제 발송 가능 여부는 인포뱅크 사전등록 여부가 결정한다.

| 입력 | 결과 |
|---|---|
| `02-1234-5678` | OK → `0212345678` (하이픈 제거 후 저장) |
| `070-4158-2540` | OK → `07041582540` |
| `1588-1234` / `1544-0000` | OK (전국대표번호 8자리 허용) |
| `2141234` | 거부 — 0으로 시작하거나 1588 형태여야 함 |
| `0212` | 거부 — 자릿수 오류 |

### 9-4. 운영 도입 순서 (권장)

발신번호가 기관별 필수이므로 자연스럽게 점진 도입이 된다.

1. 배포 + DDL 적용 → 전 기관 OFF, 발신번호 전부 비어 있음 (아무 일도 일어나지 않음)
2. 시범 기관 1곳: 발신번호 등록 → 기관 스위치 ON
3. 전역 마스터 ON → **그 1곳만** 발송 시작. 실제 도달 확인
4. 이후 번호 등록이 끝난 기관부터 하나씩 스위치를 켠다
